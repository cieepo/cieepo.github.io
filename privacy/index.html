Privacy Policy

Effective: 11 November 2026 · Applies to the JARVIS app and to this website.

1. Who operates JARVIS

JARVIS is software written and operated by one individual, Jonatan ("the developer", "I"), as a tool for the developer's own personal and professional use. It is not offered to the public: the only person whose Google data it handles is the developer, using the developer's own Google accounts. Contact: peciojonatan@gmail.com.

2. What works today and what is planned

As of the effective date JARVIS does not process any Google user data and is not a finished assistant.
  • Tested so far (technical tests, no Google data): secure access from the developer's phone to the home server through an encrypted private network; speech recognition running locally on the server; a technical connection to Anthropic's Claude models; push notifications to the developer's phone.
  • Next test (in preparation, not yet done): signing in with the developer's own Google account and sending one test email to the developer's own address.
  • Planned, does not work yet: searching and summarising Gmail messages, preparing drafts, sending or organising messages on the developer's instruction; calendar and task planning; voice answers; a conversation interface; encrypted backups.
This policy describes how Google user data will be handled once access is granted. It will not be used in any other way. If the plans change, this policy will be updated first and the new use will not start before then.

The full text of a message is meant to be fetched when it is needed for a request and not kept as a separate mail archive.

5. Anthropic and AI processing

JARVIS uses Anthropic's Claude models through the Claude Agent SDK, signed in with the developer's own Claude subscription. Anthropic processes the text it receives under its own Consumer Terms of Service and Privacy Policy.

  • Rule on training. Anthropic lets account holders choose whether their conversations may be used to improve Claude models (Anthropic's data-usage documentation). The developer's rule for JARVIS: JARVIS will not be connected to any Google account, and no Google user data will be sent to Claude, until that setting has been switched off, and only for as long as it stays off. JARVIS itself does not use Google user data to develop, improve or train any generalized or non-personalized AI or machine-learning model, and does not transfer it to anyone for that purpose.
  • Exceptions outside JARVIS's control. According to Anthropic's published documentation, some content can be used or kept by Anthropic even when that setting is off: content that Anthropic flags for safety review, and content a user explicitly reports as feedback (for example through a feedback command or thumbs up/down; transcripts submitted through feedback commands are documented as retained for 5 years). The developer will not submit feedback on conversations that contain Google user data. Because flagging for safety review is decided by Anthropic and cannot be excluded, JARVIS sends Claude only what a request needs.
  • Retention at Anthropic. With the setting off, Anthropic documents a 30-day retention period for consumer accounts and states that deleted conversations are removed from its back-end within 30 days (documentation read on 11 November 2026; please check the linked pages for the current terms).
  • Minimisation. JARVIS does not send credentials, tokens or whole mailboxes.

6. Limited Use of Google user data

The use of information received from Google Workspace scopes (the Gmail API) will adhere to the Google API Services User Data Policy, including the Limited Use requirements, and to the Google Workspace User Data and Developer Policy. In particular:

  • Google user data is used only to provide and improve the user-facing features described in this policy, visible in the app, for the account holder.
  • It is transferred to others only as described in section 4 to provide those features at the account holder's request, for security purposes, to comply with applicable law, or as part of a merger or sale with the account holder's prior consent.
  • It is not used for advertising, not sold, and not used to determine credit-worthiness or lending.
  • Humans do not read it, except the account holder, with the account holder's consent for specific data, for security purposes, or where required by law.
  • It is not used to create, train or improve generalized AI or machine-learning models.

7. Storage and security

  • OAuth access and refresh tokens are stored encrypted at rest (operating-system data protection bound to the user account on the server). Data is transferred only over encrypted connections.
  • The server runs as separate, limited operating-system accounts; the app that talks to the AI cannot change its own program files.
  • Stored data is kept only for as long as the developer uses JARVIS with that Google account, and is deleted as described in section 8.

8. Revoking access and deleting data

  • Revoke Google access at any time in your Google Account: myaccount.google.com/permissions → JARVIS → Remove access. From that moment JARVIS can no longer read or send mail from that account, because the stored token stops working.
  • Deletion is currently manual. JARVIS does not yet delete data automatically after access is revoked. After revocation, or after a request sent to the contact address above, the developer deletes by hand, on the home server: (1) the encrypted token file of that account; (2) the stored message and thread identifiers and headers, drafts, copies of sent messages and conversation-history entries related to that account; (3) the same data in any backup copy, once backups exist. The developer does this without undue delay and in any case within 30 days, and confirms by email on request.
  • Data already sent to Anthropic or ElevenLabs is governed by their retention rules (for Anthropic see section 5); the developer cannot delete it earlier than those rules provide.
  • Automatic deletion is planned. This policy will be updated when it exists.
